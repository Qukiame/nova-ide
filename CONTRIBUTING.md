# Контрибьюшн в Nova IDE

Спасибо, что хотите внести вклад в Nova IDE! Этот файл описывает, как это сделать.

## Кодекс поведения

Участие в проекте подразумевает соблюдение норм вежливости. Будьте
уважительны к другим контрибьюторам. Недопустимы оскорбления,
дискриминация и токсичное поведение.

## Как внести вклад

### Сообщить о баге

1. Проверьте, что баг ещё не зарегистрирован в [Issues](../../issues)
2. Откройте новый issue по шаблону **Bug report**
3. Укажите:
   - ОС и версию (Linux: `uname -a`, Windows: версия + сборка)
   - Версию Python (`python --version`)
   - Версию PySide6 (`pip show PySide6`)
   - Шаги для воспроизведения
   - Ожидаемое и фактическое поведение
   - Скриншот / лог (если применимо)

### Предложить фичу

1. Откройте issue по шаблону **Feature request**
2. Опишите, **зачем** это нужно (какую проблему решает)
3. Предложите, **как** это может выглядеть (скриншот наброска — приветствуется)

### Внести код

1. **Форкните** репозиторий
2. Создайте ветку:
   ```bash
   git checkout -b feature/my-cool-feature
   # или:
   git checkout -b fix/issue-42
   ```
3. Внесите изменения. Стиль кода:
   - Python 3.9+, PEP 8
   - Длина строки — до 100 символов
   - Отступы — 4 пробела
   - Документируйте публичные классы/функции (docstring в тройных кавычках)
   - Имена переменных/функций — `snake_case`
   - Имена классов — `CamelCase`
4. Проверьте локально:
   ```bash
   pip install -r requirements.txt
   python nova_ide.py
   # протестируйте свой сценарий
   ```
5. Коммитьте с понятными сообщениями:
   ```
   feat: добавлена подсветка парных скобок
   fix: исправлен вылет при открытии пустого файла
   docs: обновлён README
   refactor: разбит MainWindow на модули
   ```
6. Запушьте и откройте **Pull Request** в ветку `main`:
   ```bash
   git push origin feature/my-cool-feature
   ```
7. В описании PR укажите:
   - Что делает
   - Зачем (ссылка на issue, если есть)
   - Как тестировалось

## Стиль коммитов

Используем [Conventional Commits](https://www.conventionalcommits.org/):

| Префикс | Назначение |
|---|---|
| `feat:` | Новая фича |
| `fix:` | Исправление бага |
| `docs:` | Изменения в документации |
| `style:` | Форматирование, точки с запятой и т.п. (без кода) |
| `refactor:` | Рефакторинг без изменения поведения |
| `perf:` | Улучшение производительности |
| `test:` | Добавление тестов |
| `chore:` | Сборка, зависимости, CI |

## Структура кода

`nova_ide.py` — пока один файл. Структура сверху вниз:

1. Импорты
2. Константы палитры (`C_BG`, `C_ACCENT`, …)
3. `LineNumberArea` — виджет номеров строк
4. `CodeEditor` — редактор кода (QPlainTextEdit + подсветка + поиск)
5. `HighlighterBase` + 8 классов подсветки (Python/JS/HTML/CSS/JSON/Cpp/Sh/MD)
6. `FindReplaceBar` — панель поиска/замены
7. `FileTreeView` — файловое дерево
8. `EditorHolder` — менеджер вкладок
9. `MainWindow` — главное окно
10. `main()` — точка входа

Если файл станет слишком большим — разобьём на пакет `nova_ide/` с
модулями. Но пока один файл = проще запускать и собирать.

## Добавление подсветки нового языка

1. Создайте класс `XxxHighlighter(HighlighterBase)` по образцу
   существующих (например, `PythonHighlighter`)
2. В `CodeEditor.set_highlighter_for` добавьте расширения в `hmap`
3. В `MainWindow.on_tab_changed` добавьте расширение в `lang_map`
4. В README обновите таблицу поддерживаемых языков
5. В CHANGELOG отметьте в `[Unreleased]`

## Сборка и проверка

```bash
# Установка зависимостей
pip install -r requirements.txt
pip install -r requirements-dev.txt

# Запуск
python nova_ide.py

# Сборка Linux ELF
pyinstaller nova_ide_win.spec --noconfirm --clean
./dist/NovaIDE

# Линтинг (опционально)
flake8 nova_ide.py --max-line-length=100
black --check nova_ide.py
```

## Релизы

- Версии по [SemVer](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`
- Теги формата `v1.0.0`, `v1.1.0` и т.д.
- При создании тега `v*` GitHub Actions автоматически соберёт `.exe` и
  опубликует его в Releases
- Перед релизом:
  1. Обновить `CHANGELOG.md` — перенести `[Unreleased]` в новый раздел
  2. Обновить версию в README (если есть)
  3. Создать тег: `git tag -a v1.1.0 -m "Release v1.1.0"`
  4. Запушить тег: `git push origin v1.1.0`
